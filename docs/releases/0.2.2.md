# Release 0.2.2 — A project saved to the computer, and the actions on what it holds

The row of section 15 of the Zemp Specification: "0.2.2 | 0.8.0 | A project saved to the computer, and the actions on what it holds (#208): **Export project…** as a zip, in every browser, and the opening of an exported zip as a new project; the request for persistent storage and the reminder to export (#117, the parts that need no run record); a project renamed, duplicated and deleted; **New script**, files added into any folder, and a file renamed, moved, duplicated, deleted and saved to the computer; a folder made, renamed, moved, deleted and saved as a zip".

How to read this file: as the checklists of 0.1, 0.2 and 0.2.1. Each step is small enough to finish and commit in one session. **[engine]** marks a hard or foundational piece (the zip written and read, the operations on a project's storage, which a closed tab must never leave half done); **[function]** marks a control on screen over machinery that exists. The owner chooses the model for a session from the tag. Written on 22 November 2026, at "Start release 0.2.2"; no code is written before the owner's "go".

## What the reading found

1. **The previous release is tagged and the tree is clean:** `v0.2.1` on 7754937; one commit after it (eb03ce8) mends a test's helper and changes nothing of the app.
2. **The row, and the register.** #208 (decided 22 November 2026) gives the scope in three groups, projects, files and folders, and places **Open folder…** with the 0.5 desktop beta. #117's dated paragraph says which of its parts are built here: **Export project…**, the opening of an exported zip (without **Verify**, without the package's first page, without a pinned engine), the request for persistent storage, the reminder to export. `docs/spec/` is at Zeff 3159c99, where both stand.
3. **What the specification says of them.** Section 10: projects of Zemp on the web live in the browser's private file system, which is lost if the site's data is cleared or the browser evicts it, "so Zemp web asks the browser for persistent storage when the first project is created; when that is refused, or a project has not been exported for 30 days, a line in the status bar says so, with **Export project** in ⌘K, and nothing is exported without the user". Section 5 (the welcome screen): a zip opened "refuses a path that would leave the project and a package larger than the memory budget". Section 3: a project is a folder with `zeff.toml`, `scripts/`, `functions/`, `data/`, `output/` and the engine's own `.zeff/`; a Scratch project "can be promoted to a named project in one step". The Engine Specification, section 2: `zeff new` writes a `.gitignore` that leaves out the caches, the run records, the lock, `.zeff/session.zeff` and `.zemp/views.json`.
4. **What stands today in the code.** `Project.rename` and `Project.remove` for a file and `Projects.remove` for a project exist with unit tests, and nothing on screen calls them. The Project pane (`ProjectTree.svelte`) offers one control, **+**, which adds a data file under `data/`. A script is made only by `:save` in the console line. **Projects ▾** in the top bar goes back to the start screen and is not a menu. A project's folder in the browser's storage is made from its name (`folderOf`), and a new project is refused where that folder is taken: once a project can be renamed, a name and a folder part company, so `create` must look for a free folder and compare names.
5. **What a script writes cannot be had, and is not even kept** (corrected at step 3, 22 November 2026: the plan first said such a file "goes into the project in the browser's storage"; it does not). `export` and `save` write into the engine's own copy of the project, in the worker's memory: the file is in no pane, cannot be taken out, and is gone when the tab closes. The Engine Specification (section 2) has them write "under the project folder", which in the browser is the browser's storage. So before a project is exported or a file saved, what a run writes must be brought into the project: step 2b.
6. **The engine is told of files already.** The session and the language engine each hold a copy of the project and have `changed(path)` and `removed()` (the whole project given afresh): a rename, a move or a deletion uses them, and needs nothing new of the worker.
7. **A zip needs no dependency.** Every browser the alpha supports has the deflate of a zip built in (`CompressionStream` and `DecompressionStream`, "deflate-raw"), and so has Node, where the unit tests run. What is left is the container: the headers, the directory at the end and a CRC-32. So the zip is this repository's own, about two hundred lines, held in tests to a reference reader and writer (Python's `zipfile`, which this Mac and GitHub's machines have): no licence to record and nothing to keep up to date.
8. **No dialog.** The Lite build holds no dialog (the edition check). A name is typed and a deletion confirmed in the row itself, as **New project…** is named now.
9. **Open decisions due at 0.2.2:** #208, decided; #117 in part, decided. Risks the row touches: R4 (the build grows by the zip and the menus; measured at each step), R10 (a visitor's work lost is a visitor lost).
10. **Carried from 0.2.1, not part of this row:** the reader test (owed at Zeff 0.9.0) and the checks by hand, the owner's; the occasional slow ⌘↵ on GitHub's machine, cause not found, watched at each deployment.

## What 0.2.2 leaves out

No new function of the catalogue belongs to a Zemp release.

## Questions only the owner can answer

Each has a recommendation; "go, as recommended" takes them all.

1. **How a deletion is confirmed, and whether it can be undone.** The browser's storage has no bin. _Recommended:_ a deletion asks once, in the row: it names the file, or the folder and how many files go with it, says that it cannot be brought back, and offers **Delete** and **Keep**. Nothing is undone in 0.2.2. The deletion of a project offers **Export project…** first.
2. **`scripts/main.zeff`.** The engine runs it where no script is named, and the app opens it first. _Recommended:_ it is not renamed, moved or deleted; every other script is. (`zeff.toml` and the folders `scripts`, `functions` and `data` are fixed in the same way, which is settled.)
3. **Moving a file by dragging its row.** _Recommended:_ left out of 0.2.2. **Move to…** in the row's menu does it and is reached by the keyboard; dragging would be a second way to the same end.
4. **The Scratch project.** It is always there, and the specification says its work "can be promoted to a named project in one step". _Recommended:_ it is not renamed; **Duplicate…** makes a named project of it, which is that one step; and in place of **Delete** it has **Reset…**, which puts back its examples as a first visit has them, after the same confirmation.
5. **What an exported zip holds.** _Recommended:_ a file `<the project's name>.zip` with one folder of that name in it, holding `zeff.toml`, `scripts/`, `functions/`, `data/`, `output/` and anything else the visitor put in the project; left out are the app's own view state (`.zemp/`) and what `zeff new` keeps out of Git (the engine's caches, run records, lock and console session). So the zip, unpacked, is a project the `zeff` command line runs.
