# Zemp Lite 0.2.2 — A project saved to the computer: release notes (draft)

_Draft of 23 November 2026, written at step 10. It is finished at "Release 0.2.2", after the
pre-release routine (step 11). Until then the sections marked "at the close" are open._

## What it is

The second patch of the alpha, on the same engine, the released Zeff 0.8.0 (commit
`6bfa6c55a5584e4e038fc828fef900a30f0856c3`, tag `v0.8.0`): a reader's work can leave the browser
and come back, and a project's files, folders and the project itself can be made, renamed, moved,
copied and deleted on screen. Decided by the owner on 22 November 2026 (open decision #208). Its
address is `https://lite.zeff-lang.dev`.

## What shipped

**A project out of the browser, and back.** **Export project…** (in ⌘K in a project, and in each
project's menu on the start screen) gives the whole project to the computer as one zip, named for
the project, with one folder in it that holds the project as the `zeff` command line would find
it: `zeff.toml`, the scripts, the functions, the data, what the scripts wrote. Unpacked, `zeff run`
runs it. Left out are the app's own view settings and the engine's own caches. **Open a project's
zip…** on the start screen opens such a zip, or a project's folder zipped on the computer, as a new
project; one that cannot be opened safely (no project in it, a path that would leave the project,
two names that differ only in capitals, a damaged or password-protected zip, one too large) is
refused in a sentence and nothing is made.

**What a script writes is now the project's.** A table saved with `save` and a figure exported
with `export` are kept in the project, shown in the Project pane under `output/`, and are in an
exported zip. Before this release they stayed inside the engine, in no pane, and were lost when
the tab closed.

**A file or a folder saved to the computer.** Every row of the Project pane has a menu (**⋯**):
**Save a copy…** gives a file to the computer as it is, **Save as a zip…** a folder.

**Files and folders.** The Project pane's **+** makes a **New script** or a **New folder**, or
adds files from the computer; each folder has the same for itself, so files go into any folder.
A row's menu has **Rename…**, **Move to…**, **Duplicate** and **Delete…**. A name is typed, and a
deletion confirmed, in the row itself; ⌘K has the same for the project open (**Project: new
script…**, **Project: new folder…**, **Project: add files…**) and for the file shown (**File:
rename…**, **move…**, **duplicate**, **delete…**, **save a copy**). A script that is open follows its file to a new name or
folder, with what was typed and the results of its run. Renaming or moving a file rewrites no
script: where a script names the old path, the pane says which script and line, each a link.
A deletion is asked once, says what goes and how many files, and cannot be undone. `zeff.toml`,
the folders `scripts`, `functions` and `data`, and `scripts/main.zeff` are not renamed, moved or
deleted.

**Projects.** A project's menu on the start screen has **Rename…**, **Duplicate…**, **Export
project…** and **Delete…**; the same are in ⌘K for the project open. The Scratch project is not
renamed or deleted: **Duplicate…** makes a project of the reader's own name from it, and
**Reset…** puts its examples back as a first visit has them.

**Whether the browser keeps the work.** When a project is first made the browser is asked to keep
its storage for good. Where it does not agree, the status bar of a project says "the browser may
clear this project" and when it was last exported, with **Export project…** beside it; where it
agrees, the line appears only when a project has not been exported for 30 days. The start screen
says which holds.

**Mended.** The view state of a project (which panes are open, what is unfolded) was written a
fifth of a second after the _last_ change, each new change putting it off: a reader who opened a
pane and went straight on working could find it closed the next time. It is now written after the
first change, and what is set as the page is left is kept too. A file being rewritten at the
instant it was read was taken for a file that is gone. A row's menu near the window's foot ran off
the screen. ⌘K lists first the commands that hold the words as they were typed, so "new project"
finds **New project…** before the commands that only hold both words.

## Breaking changes

None for a project's files. On screen: the Project pane's **+** is a menu (it added a data file
at once before; **Add files…** in it does that now). A project made before this release opens as
it was.

## Reference versions

As in 0.2.1: every output is held to what the released Zeff 0.8.0 command line prints, writes and
says for the same script, byte for byte. New at this release: a zip written here is read by
Python's `zipfile`, and one written by it is read here; a project exported from the hosted alpha
is run by the released `zeff run`.

## What is left out, and why

**Open folder…** (a project that lives in a folder of the computer) comes with the desktop app,
and then in Chrome and Edge (#208). **Open a replication package…** with **Verify** waits for the
run record of Zeff 0.11.0 (#117). A deletion cannot be undone: the browser's storage has no bin.
A file is moved by **Move to…** in its menu, not by dragging its row (the owner's answer of 22
November 2026). A zip dropped on the window is not opened; it is chosen.

## Known issues

- The known issues of 0.2.1 stand, among them: the reader test not run, the checks by hand not
  made, and the occasional wait of two to three seconds before ⌘↵ on GitHub's machine in
  Chromium, its cause not found.
- Where the browser has not agreed to keep the storage, which most browsers do not on a first
  visit, the reminder stands in the status bar from the first project on.
- In Safari a button takes the Tab key only with Option held, unless the reader has set
  otherwise; the menus and questions of this release are reached that way there.

## To try it

Open `https://lite.zeff-lang.dev` in Chrome, Edge or Safari, press **Open Zemp Lite**, choose
**Scratch project** and press **Run**; then ⌘K, **Project: export…**. The address is not announced
until the trademarks are filed (#37).
