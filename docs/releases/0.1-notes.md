# Zemp Lite 0.1 — The prototype

Released 18 November 2026, version 0.1.0, tag `v0.1.0`, after the owner had tried it on his own computer. Drafted at step 13 of `docs/releases/0.1.md` on 15 November and completed on the day of the release.

Zemp Lite 0.1 is the prototype the release plan asks for (Zemp Specification, section 15): the workspace and the plot viewer, in the browser, on the released engine Zeff 0.7.0. It is private: it runs on the owner's computer and is hosted nowhere. Nothing in it is promised to stay as it is; the alpha, Zemp 0.2 with Zeff 0.8.0, is the first release meant for others.

## What it is

- **Projects** kept in the browser's private storage, one to a window: a welcome screen with New project, the Scratch project (a worked example on the shipped `wages`) and the recent projects; a data file added from the computer. Where a browser gives a page no storage (a private window of Safari), projects last for the tab and the screen says so.
- **The workspace in two layouts.** *Inline*, which a project opens in: one column, each statement's output directly under it, its time in the margin. *Panes*, as the owner's mockup has it: a left panel with the tabs Project and Objects, the editor tabs, and the Output panel under the script. One click switches; the layout, the panel sizes and the open tabs are kept with the project.
- **The editor**: line numbers, the current line marked, Zeff's code coloured in the design guide's categories, saving as it is typed, Run from the keyboard (⌘⇧↵, and ⌘↵ until the statement ranges of Zeff 0.8.0; the Run button names its keys).
- **Run**: the script runs in the engine, in a worker of its own, so the page never freezes; each result under the line that made it; a warning as a card with its code and sentence, an error under its line with the engine's excerpt and advice; the running statement marked, with Cancel; output of a script edited since marked "edited · not run". When the engine's check refuses a script, nothing runs: the results of the run before stay on the page, marked as not run, with what the check found under its line.
- **⌘K** with every command of the window, and a **console line** that runs a statement after the script without adding it to the script.
- **Plots**, drawn by the engine itself at the size of the place they are shown in, and laid out afresh when it is resized: under their statements, and in the **plot viewer**, with the gallery strip, two to four plots compared side by side, a plot popped out into its own window, the journal sizes (one column, two columns, slide), and a figure saved as SVG, PDF or PNG with the Zeff statement that does the same.
- **The look** of the owner's design guide: the logo and its violet, the three font families (shipped inside the app), light and dark, the code size control.

## After the owner's trial

He tried the prototype on 15 and 16 November and three things were changed, each recorded in `docs/decisions.md`:

1. **A run leaves the reader where they were.** In Inline and in the Output panel the page went to its top at each run; the reader's place is now kept through the run, in every browser.
2. **One mistake no longer empties the page.** When the engine's check refuses a script, the results of the run before stay, marked as not run, with what the check found under its line (his choice: keep the last results).
3. **The keys of Run** are named on the button. Running one line waits for the 0.2 alpha, with the statement ranges of Zeff 0.8.0 (his choice).

## Breaking changes

None: this is the first release. Nothing in it is promised to stay as it is: the alpha, Zemp 0.2 with Zeff 0.8.0, is the first release meant for others, and its editor will be the margin editor the owner adopted on 18 November 2026 in place of the Inline layout (`docs/decisions.md`).

## Functions

Zemp has no functions of its own. Every function a script calls is Zeff 0.7.0's, run by the released engine inside the app.

## What it leaves out, and why

For the alpha, with Zeff 0.8.0: the language server in the editor (completion, hover, live diagnostics, formatting) and **Check**; running the statement at the cursor; the data and variables viewers; the Log with `zeff explain`; "Report a problem"; public hosting; **Open folder…**; the Start screen. Waiting on the engine handing plots over as scenes: a redraw within one frame; Focus on a panel of a faceted plot; Inspect; Compare on shared axes; History; a dark ground under a plot. Later rows of the release plan: causal graphs (Zeff 0.10.0), opening a replication package and the storage reminder (0.11.0), the desktop (0.5), the Git panel (1.1).

Four things the prototype does in a way of its own, because the engine of 0.7.0 does not yet tell an interface what it would need, each recorded in `docs/decisions.md` and each replaced when the engine does:

| What | How the prototype does it | What replaces it |
| --- | --- | --- |
| A plot at the size of its pane | Runs the script once more with an `export` added at that size, and shows the file the engine wrote | The engine handing a plot over without a run (asked of Zeff 0.8.0) |
| Where a statement ends | From where the next statement began, or from the statement's shape | The statement ranges of Zeff 0.8.0 (#86) |
| The colours of code | A small reader of Zeff's words, by shape | The language server's semantic tokens |
| A console statement | Runs the script, the statements kept, then the new one, as `zeff repl` does | A session the engine keeps for an interface |

## Validation

- **The engine in the browser is the released engine.** The eight sample projects of the Zeff repository at v0.7.0 (`data_cleaning`, `first_engine`, `panel`, `plots`, `regression`, `simulation`, `tests`, `user_functions`), run through this repository's worker, print and say what Zeff expects of them, byte for byte (`npm run check:samples`). Three of them, and the Scratch example, and four short scripts (plain, with warnings, stopping at an error, refused by the check), are run through the interface itself in both browsers, and what the Output panel shows is what the released `zeff run` 0.7.0 prints and says, to the byte.
- **A figure is the engine's figure.** The text the interface composes to draw the example's two plots, run through the worker, writes the files the released `zeff run` writes for the same text, byte for byte; a figure saved from the viewer as SVG, PDF and PNG at one-column size is the file the released command line writes.
- **The specification's sample script** (`docs/spec/zeff_samples.zeff`) is written for Zeff 1.0 and uses a module of a project of its own; the engine of 0.7.0 refuses it before it runs, and the prototype shows the refusal as the command line words it. The sample projects above stand in its place.
- **The reference** for every output is the released `zeff run` 0.7.0. No output of R, Python or Stata is used by this release: the engine's own validation against them is Zeff's, in its release notes.
- **The tests.** 117 unit tests; the worker's 7 native tests and 8 tests of its messages; 164 browser tests, 82 in Chromium and 82 in WebKit, of which 1 is skipped by design (the private-window test in Chromium, which keeps storage there). The mouse-drag test is skipped only where a test browser does not deliver the mouse where it is aimed, as WebKit on this Mac sometimes does not; on GitHub it runs in both browsers. Every text colour reaches 4.5 to 1 against its grounds in both themes, by a test.
- **The routine of the release**, run on 18 November 2026 on this Mac (macOS, Apple silicon) and on GitHub (Linux), each in Chromium and in WebKit: format, lint, types, the worker's Rust (format, clippy with warnings denied, tests), the worker built and measured, the eight sample projects, the unit tests and the browser tests, all green.
- **Every failed run on GitHub, and why.** Of the 37 runs before the release, 5 failed, all in WebKit: twice the reader's place after a run (15 and 16 November, before it was mended on 16 November); twice the test of a plot in a narrowed pane, which measured the figure before its last redraw had come (17 November, with no change to the code between; the plot was right and the test asked too early, so it now waits for the redraw, `docs/decisions.md`, 18 November); and twice a page that WebKit did not load within thirty seconds at the start of a test (16 and 18 November; known issue 10). Each run after passed.

## Known issues

1. **A redraw is a run of the script.** For the example it takes about 40 ms; for a long script it takes as long as the script. It waits for the engine's hand-over of plots.
2. **A console statement runs the whole script again**, for the same reason: the engine keeps nothing between two runs in a browser.
3. **Output is marked stale all at once.** When the script is edited every output is marked "edited · not run"; the finer rule of section 5, by dependency, needs what the engine does not yet tell.
4. **The end of a statement is found, not told**, so an output can stand a line too high or too low under a statement of an unusual shape. It is right for every script tested.
5. **A printed table wider than the Inline column scrolls sideways** inside its box.
6. **The undo history of a file** starts afresh when its tab is left and come back to; the file itself is always as typed.
7. **Figures are light in the dark theme**: they are the engine's print figures.
8. **Two advisories of `npm audit`** in tools of the build (`deepmerge`, `minimatch`), neither in the app, neither with a usable fix published.
9. **For the alpha's host:** it must send the two isolation headers on every answer, "not modified" ones included (the prototype is mended against a host that does not), and section 5's paragraph "The look" still carries the look of #115 where the prototype follows #146.
10. **Twice, on GitHub, WebKit did not load the page at the start of a test** within its thirty seconds (16 and 18 November), and the next run passed. It has never been seen on this Mac. It is watched; if it grows, the page load alone will be given a second try.

## To try it

In a terminal, in `~/dev/zemp-lite`: `npm run build` and then `npm run preview`, and open the address it prints (`http://localhost:4173`) in Chrome, Safari or Edge. Choose **Scratch project** and press **Run**.
