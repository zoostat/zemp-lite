# Release 0.2 — The alpha

The row of section 15 of the Zemp Specification: "0.2 alpha | Zeff 0.8.0 | **Zemp Lite web preview**, the first public way to write Zeff in an IDE: workspace, editor with the language server, data viewer, plot viewer; "Report a problem"; the reader test of Zeff syntax runs on this alpha". Its editor is the margin editor, adopted by the owner on 18 November 2026 (open decision #174; the design is `~/dev/handbook/zemp-lite-margin-editor/zemp_lite_margin_editor_specification.md`, version 0.9, outside the repository). Of that design, the alpha builds the steps its section 22 gives the alpha, and nothing later: the margin with its notes, results opened under their statements, the three controls, a refused script, the run's facts and what the run said, Plots with its list (step 1); then ⌘↵, **Run to here** and the loop inspector of #76 (step 2). The engine is the released Zeff 0.8.0 (the tag `v0.8.0`, commit 6bfa6c5), used only through its public crates; `~/dev/zeff` is read and never edited from here. What it unlocks: the first outside readers of Zeff, the reader test (risk R10), and Zemp 0.3 on Zeff 0.9.0.

How to read this file: as the checklist of 0.1. Each step is small enough to finish and commit in one session. **[engine]** marks a hard or foundational piece (the worker and what it asks of the engine, the structure every later screen stands on, the language services, the data grid, the hosting); **[function]** marks interface work on machinery that already exists. The owner chooses the model for a session from the tag: the most capable for planning and for [engine] steps, the next for [function] steps. A change to the normative text is made in the Zeff repository's copy only; a design question the text does not settle becomes an open decision there. A step that turns out too large is split here, not pushed through.

## What the reading found

1. **The copy of the specification is behind.** `docs/spec/` is at Zeff commit 2e90407; Zeff now stands at 08a18a4: the release 0.8.0 (6bfa6c5), then the closing of #18 and the moving of #151 and #31 to 0.11.0 (1614f7c), then the notes of Zemp Lite entered as #174 to #197 (08a18a4). Seven of the ten files differ, among them the Zemp Specification (the counts of section 11 and the 1.1 row of section 15) and the register (760 lines). `zeff_testing.md` and the README are unchanged. Step 1 refreshes the copy from 08a18a4, each file taken from the commit and compared with it byte for byte, as 0.1's step 1 did.
2. **The Zemp Specification still describes the Inline layout and the look of #115.** #146 places the amendment of section 5 (its paragraph "The look" included) at the first step of this alpha, and #174 the amendment of sections 2, 5, 7, 8 and 15 for the margin editor. The normative copy is the Zeff repository's, which is not edited from here; so step 1 writes the amended text, with the owner's answers to the questions below, as a note in the shared notes folder for a Zeff session to enter and log, and this copy is refreshed again when it stands there. The build follows the decided rulings meanwhile, as 0.1 followed #146.
3. **What Zeff 0.8.0 gives an interface** (read at the tag; the details are in `docs/decisions.md` from step 1). The events of a run are those of 0.7.0, unchanged: a statement started with its first line, finished, a pass of a loop by its number, and printed text. Everything new is inside `zeff-engine`, as Rust a worker can call, and the browser build of the engine (`zeff-web`) passes little of it on. So Zemp's own worker grows:
   - *Given by the engine at 0.8.0 and to be passed on by the worker:* each statement's range (`language::outline`, built at Zeff's step 8b), so the end of a statement is no longer found by the interface; each statement's printed output and what it said, at a width asked for the whole run (`Outcome.output.statements`, `RunOptions.width`); each binding's name and type from the checked program, and each kept frame's rows, variables and memory; the check of a script with its findings as structured records (the **Check** button); the dependencies of each statement (`dependencies::graph`, `needed_by`); completion, signature help, hover, live diagnostics, formatting, folding and snippets (`zeff_engine::language`, and the protocol server `zeff-lsp`); help pages (`help::help_text`); the explained page of every code (`zeff_web::explain`); "Report a problem", a local bug report with its shrunk script (`bug_report::build`); a frame's variables with their labels, value labels, missing codes, measure, unit, question and source, in the Arrow it already sends.
   - *Not given at 0.8.0, so the alpha works round it, keeping every character the engine's:* the size of a result that is not a frame (C5): its note gives the engine's type and then the first line the engine printed for it, as #175 provides; a print at another width (C6): asked by running again, with the figures in the same run, a quarter of a second after a resize, as 0.1 redraws a figure; results kept between two runs (C14): a run of one statement runs, from the top, the statements it needs (the engine's dependency graph) and leaves every other result as it was; a plot handed over without a run (C16, #197): the 0.1 route stays, an `export` added to the text sent; each statement's time: taken by the interface between the engine's two messages, as in 0.1; the chain of an error inside a function (C22): read from the engine's printed `= in: …, called at …` lines.
   - *Not available until a later Zeff:* run records, the result cache and a result's identity (C2, C3, C12: 0.11.0), so staleness follows the engine's dependency graph, safe side out (a statement that reads a file or draws random numbers counts as stale whenever anything above it is edited), and "Compare with run *n*" waits; the loop variable, rows and result of each pass (C23), so the loop inspector of #76 shows at this alpha what the engine tells (each pass reported, its time, what it printed and said), the rest when C23 is placed; a dark plot on screen; semantic tokens (1.1), so the code keeps 0.1's colours from its own small reader.
4. **The bundle.** Zeff 0.8.0's own worker is 2,782 kB compressed (2,535 kB at 0.7.0) with a cold start of 143 ms (52 ms), against the 5 MB and the second of risk R4; Typst is not linked (#172), so no PDF of a script with its output is in this alpha.
5. **Shipped data.** `wage2`, which 0.1 hoped to use for the alpha's instrumental-variables example, is not shipped. Zeff 0.8.0 ships `wages`, `firms`, `sleep` and `staff` (an encouragement design for `ivreg`), with nine sample projects, `instruments` among them. 0.8.0 also renames six functions (`days_between` → `time_between`, `quantile_group` → `bin`, and others) and refuses `x == NA`; the examples and the expected outputs here are held to 0.8.0 at step 2.
6. **Open decisions due at this alpha:** #27 (a Zemp server), #37 (the trademarks), #74 (the Help pane), #75 (the data viewer), #176 (R2, R8, R9 of the margin editor), #177 (not a notebook), #178 (the form of a section comment only), #181 (Run from here), #183 (the error's trail), #187 (time and memory), and the amendments for #146 and #174. Decided and built here: #76 (Run to here and the loop inspector), #114 (Copy as Zeff in Lite's viewers, sorts, filters and variable changes, never rows), #116 layer 1 (a cookie-free count of visits on the web host), #33 (the line below 1,200 pixels), and the hosting of #27 (Cloudflare Pages at `lite.zeff-lang.dev`, the isolation headers on every answer). The engine items of #175 and #197 are Zeff's, put to the owner at "Start release 0.9.0"; this alpha is planned on 0.8.0 alone. A hand-over note on what 0.8.0 gives an interface is left for that session in the shared notes folder.
7. **The testing handbook at this release.** Its kinds of test that apply, as in 0.1: unit, snapshot, script (each output held to the released `zeff run` 0.8.0, now at each width), bundle and start-up; and, new from Zemp 0.2, **edition builds** (Lite builds without any point-and-click module). Section 2.4 item 4, the reader test, runs on this alpha (section 15's row; Zeff skipped it at 0.8.0 by the owner's decision and owes it at 0.9.0). The acceptance tests of the design's section 21 that concern what this alpha builds are written as browser tests in the step that builds each.

Paper and **Export script with output** come with #141 and #172. Diagrams come with Zeff 0.10.0 and later.

### Due now: the product and the public preview

1. **#27, a Zemp server (paid sync, server compute, self-hosting).** Hosting and sync through the user's own folder sync are ruled; open is whether Zemp ever runs a server of its own. *Recommended:* no Zemp server before 1.0. The alpha sends nothing to any server but the host's cookie-free count of visits (#116); section 13 stays as written; the question returns with the paid tiers (#35, #36).
2. **#37, the trademarks.** The register asks for "Zeff" and "Zemp" to be filed in your home jurisdiction before the public alpha. *Recommended:* the alpha is built and hosted now, and its address announced (the website, colleagues, the article) only once the applications are filed. The filing is yours or a trademark agent's to make; this is not legal advice.
3. **The reader test.** *Recommended:* one reader test serves Zemp 0.2 and Zeff 0.9.0 together: five to eight readers you choose (students, referees, colleagues), each given about ten short scripts in the hosted alpha and asked what each model does; I prepare the scripts and the form, you run it, and what they misread is fixed or recorded before "Release 0.2".
4. **#74, a Help pane.** *Recommended:* yes: a Help panel at the side of the Script place, hidden until asked for (F1, ⌘K, or **Explain** on a warning), following the function under the cursor (a switch stops it) and showing a code's explained page; the pages are the engine's, shipped with it.
5. **#75, the data viewer.** *Recommended:* option A, in the Data place: a grid drawn as it is scrolled, the first column frozen, a statistics header on every column (type, missing count, a small distribution, all asked of the engine), search with matches marked, a live count of rows under a filter, copying a range, variables shown and hidden (your ruling of 18 November); read-only, with **Copy as Zeff** (#114). Option A's Objects tree is replaced by Data's list of frames, each by the statement that made it.
6. **#177, "Zemp Lite is not a notebook".** *Recommended:* A: no cells; the script stays one plain text file that `zeff run` runs from top to bottom, and the statement is what is run, shown, folded and marked stale.
7. **The example a first visitor opens.** *Recommended:* the Scratch project holds the margin editor's own script on `wages` (returns to schooling: a summary, a histogram, three regressions, `report`, a scatter), whose notes the whole design is drawn on, and a second script, `instruments.zeff`, Zeff 0.8.0's sample on `staff` with `ivreg`, in place of the `wage2` example 0.1 hoped for, since `wage2` is not shipped.

### Due now: the margin editor

8. **R2, the Panes layout.** *Recommended:* kept for this one release beside the margin editor, as 0.1 built it, then reviewed at 0.3 with what alpha users say.
9. **R8, the keys.** *Recommended:* as the editor's document has them: ⌘↵ the statement, ⌘⇧↵ the script, ⌘K everything, ⌥↵ open or fold a result, F1 help, ⌃` the console; every action also in ⌘K; no key a browser keeps.
10. **R9, what ⌘↵ runs.** *Recommended:* the statement with every statement it reads, so that no result on the page is ever other than the script's; at 0.8.0, which keeps nothing between two runs in a browser, that means those statements run again from the top. The Engine Specification's paragraph on running code interactively is amended to match.
11. **R4 (#178), the comment that begins a section.** `// # Data` (with `// ## Cleaning` a level below) or `// ── Data ──`. *Recommended:* `// # Data`, read as a Markdown heading and with levels. Only the form is due now; the outline comes with #178.
12. **R14 (#183), the error's trail.** *Recommended:* yes, at this alpha: an error inside a function lists each link of the chain the engine printed, each a link to its line, each file opening with a note on the lines named; nothing run again; the pass of a loop added when the engine gives it.
13. **R15 (#76), Run to here in the gutter.** *Recommended:* yes: the words *Run to here* on resting over a statement's line number, beside the command in ⌘K.
14. **#181, Run from here.** *Recommended:* yes, with Run to here, in ⌘K: the statements from the cursor to the end, with what they read.
15. **R19 (#187), where the time and memory went.** *Recommended:* at this alpha, in the run's facts: the statements by their time (measured by the interface between the engine's messages until the engine reports times) and the frames by the memory the engine reports.

### Not due now
