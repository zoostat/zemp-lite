# Release 0.1 — The prototype

The row of section 15 of the Zemp Specification: "0.1 prototype | Zeff 0.7.0 | Framework chosen; workspace and plot viewer prototyped on the new plot renderer". The framework is chosen (open decision #24: Svelte 5 with TypeScript, bundled by Vite, with CodeMirror 6 as the editor). What remains is a prototype of the workspace (section 5) and of the plot viewer (section 7), in the browser (sections 3 and 10), on the released engine Zeff 0.7.0. The prototype is private: it runs on the owner's computer and is hosted nowhere. What it unlocks: the alpha, Zemp 0.2 with Zeff 0.8.0, starts from an interface that already runs the engine and draws its plots.

How to read this file: as the checklists of the Zeff repository. Each step is small enough to finish and commit in one session. Zemp has no catalogued functions, so the two tags keep their purpose, the choice of model for a session, with these meanings: **[engine]** marks a hard or foundational piece (the engine's build and its worker, the hand-over of plots, the structure every later screen stands on); **[function]** marks interface work on machinery that already exists. A change to the normative text is made in the Zeff repository's copy only, to correct an error found while coding; a design question the text does not settle becomes an open decision there with a deadline release. A step that turns out too large is split here, not pushed through.

## What the reading found

1. **The copy of the specification is two commits behind.** `docs/spec/` was taken at the Zeff repository's commit 9f2b74b. Since then Zeff has moved the catalogue and the three volumes to the plan of releases after 1.0 (7440d2b, #113) and recorded the owner's ruling on the repositories (2e90407, #148: Zemp Lite public under Apache 2.0, Zemp Studio in a private repository of its own; the opening paragraph and sections 2, 3, 15, 16 and 17 of the Zemp Specification). Both were read against this plan: the rows of 0.1 and 0.2 and sections 5, 7 and 10 are unchanged, so no step moves. Step 1 refreshes the copy from 2e90407 or whatever is later.
2. **No open decision is due at Zemp 0.1.** #24 (the framework) and #146 (the look) are decided. #27 (sync and a server), #37 (the trademarks) and the amendment of section 5 for #146 are due at the 0.2 alpha; #74 and #75 (the Help pane and the data viewer) at Zeff 0.8.0. None is taken here.
3. **The look.** Section 5 of the Zemp Specification still carries the look of #115 (IBM Plex, a blue accent); the owner's later rulings of #146 replace it (Atkinson Hyperlegible Next, JetBrains Mono and Newsreader; the logo's violet). The entry of #146 says that no normative text fixes these, which is mistaken: the paragraph "The look" and its two tables do. The prototype follows #146 and the design guide; the amendment of section 5 that #146 places at the first step of the 0.2 alpha must cover that paragraph too. A note is left for the Zeff sessions, whose copy is the one amended.
4. **The released engine gives no plot to the interface.** The browser build of Zeff 0.7.0 (`zeff-web`) returns the printed output of a run and its frames; it keeps no plot and has no call that draws one at a size. The engine's public crates do not hand a plot out either. The one way to a figure at 0.7.0 is the one a script has: `export(p, "….svg", size: [width, height])`. So the prototype draws a plot by running Zeff: the interface adds an `export` at the size of the pane, in millimetres, to the text it sends, and reads the file the engine wrote. This keeps principle 2 (the interface writes Zeff and never calls the engine directly), and it means that a redraw to fit is a new run: right for a prototype, and far from the target of section 14 (16 ms). The proper hand-over is engine work for Zeff 0.8.0, which the alpha needs: the browser build keeping the plots of a run as it keeps the frames, and drawing one at a size and in a theme without a new run. A note is left for the Zeff sessions.
5. **Reading a file the engine wrote** needs a piece `zeff-web` does not have: its project in memory is private to it. Zemp therefore builds a small worker of its own from the engine's public crates at the tag v0.7.0, pinned by commit: the messages of `zeff-web` (`host.mjs`), with one more that gives back a file of the project. The Zeff repository is not touched. The released tag carries no built files, so the WebAssembly build is made here from source at that commit.

## What 0.1 leaves out

Each belongs to a later row and is not pulled forward. For the 0.2 alpha, with Zeff 0.8.0: the language server in the editor (completion, signature help, hover, live diagnostics, formatting), **Check**, running the statement at the cursor (the statement ranges of #86), the data and variables viewers, the Log with `zeff explain`, "Report a problem", and the public hosting. Waiting on plots handed over as scenes (Zeff 0.8.0): redraw within one frame, Focus on a panel of a faceted plot, Inspect, Compare on shared axes, and the dark ground of a plot on screen. Later rows: causal graphs (Zeff 0.10.0), **Open a replication package…** and the persistent-storage reminder (0.11.0), the desktop and its Terminal button (0.5), the Git panel (1.1), the offline app. The check that Zemp Lite builds without the point-and-click modules starts at Zemp 0.2 (testing handbook, section 1), when Studio's modules could first exist; nothing here depends on them.

## The routine of this repository

The testing handbook's routine (section 2.1), as it applies to an interface. On every step: the format check (Prettier), the lint (ESLint), the type check (`svelte-check` and the TypeScript compiler), the unit tests (Vitest), the browser tests (Playwright, in headless Chromium and WebKit, on a page that is cross-origin isolated), and for the worker's Rust `cargo fmt`, `cargo clippy` with warnings denied and `cargo test`; the forbidden-words check; CI read after the push. The handbook's kinds of test that apply here: unit, snapshot (the printed output shown, the figures drawn), script (a Zeff script run through the interface and compared with what `zeff run` prints), and bundle and start-up (the compressed size of the worker and its cold start, against risk R4: 5 MB and 1 second; Zeff 0.7.0 measured 2,535 kB and 52 ms). The definition of done of section 4 is for a function and has no item for a screen; each step below names its own.

## Questions only the owner can answer

1. **The fonts.** The design guide names three families: Atkinson Hyperlegible Next, JetBrains Mono and Newsreader. All three are under the SIL Open Font Licence 1.1, which is not on the standing list of licences; you allowed it for IBM Plex in Zeff 0.7.0. Recommendation: allow it for these three, fetched once from their publishers' own releases and shipped inside the app with their licence files, so that the prototype asks no outside server for a font, which the privacy rule of section 13 wants. Without your word the prototype uses the computer's own fonts.
2. **The forbidden-words check on GitHub.** The Zeff repository holds the list of words as a repository setting, which its CI job reads; `zoostat/zemp-lite` has no such setting yet, so the same job cannot run here. Recommendation: let me set the same variable on this repository, a change of a repository setting and nothing else.
3. **The example the prototype opens with.** The Scratch project needs a script and a data file to show. Recommendation: the shipped `wages` dataset of Zeff 0.7.0 with a short script of that release (a summary, a regression, a scatter with its fit, a histogram), every statement running on the released engine. The mockup's instrumental-variables example on `wage2` needs `ivreg`, which is Zeff 0.8.0, and comes with the alpha.

### B. The engine in the browser

- [x] **3. [engine] The worker.** A small Rust crate of this repository, built to WebAssembly with `wasm-bindgen` 0.2.129 (the version Zeff 0.7.0 pins), on the engine's public crates at the commit of v0.7.0 (9a3cabd): a project in memory, a file put into it, a run that tells its steps, a frame of the last run, and a file of the project given back. Its messages are those of `zeff-web`'s `host.mjs`, with the one added. The build is one script and its output is not committed. Tests: unit (`cargo test`: a run, a file read back, a file that is not there), the messages under a worker thread of Node as Zeff tests them, and the engine's version read back as 0.7.0. Done when: a script run through the worker prints what `zeff run` 0.7.0 prints, byte for byte, for the sample script of step 5.
- [x] **4. [engine] The interface's side of the worker.** One module that starts the worker on a cross-origin-isolated page (the development server sends the two headers), opens a project, sends its files, runs a script, hears each step as it starts and ends with its line, cancels through the shared flag, and restarts the worker when a project closes (Engine Specification, section 8.3, point 7). The size of the compressed worker and its cold start are measured in the routine and fail above 5 MB or 1 second (R4). Tests: unit (the messages, against a stand-in worker), browser (a script runs and its output arrives; a long run is cancelled and the page stays usable), bundle and start-up. Done when: a text box and a button on the page run Zeff and show what it printed.

### D. Plots

- [ ] **11. [engine] A plot from the engine, at the size of its pane.** The interface finds the statements of a run that end in a plot and the bindings that hold one, adds for each an `export` to an SVG file at the size of the place it will be shown, in millimetres, to the text it sends, and reads the files back through the worker (finding 4). The script the user sees is never changed, and the added lines never show in the output. A plot appears under its statement and in the Plots tab; when its pane is resized the run is made again, once the resizing has stopped, and the plot is laid out afresh, never stretched. Figures are drawn in the engine's light print theme on a light ground in both themes of the interface. Tests: unit (the text sent for a script of two plots; a size in pixels to millimetres and back), script (the SVG shown equals, byte for byte, the file `zeff run` writes for the same `export`), browser (a pane made narrower gives a figure of new proportions with text of the same size). Done when: the scatter and the histogram of the example redraw to fit; the time a redraw takes is measured and written down for the notes.
- [ ] **12. [function] The plot viewer.** Of the features of section 7, those the released engine allows. The gallery strip: every plot of the session as a thumbnail, click to show, drag to reorder. Compare: two to four plots pinned side by side (not yet on shared axes). Pop out: a plot in its own window, which redraws to fit. Journal sizes: the plot previewed at one-column, two-column and slide sizes. Export: SVG, PDF and PNG at a chosen size, each written by the engine's `export`, with the Zeff statement that made the plot offered beside it. The order of the strip and the pinned plots are view state. Tests: browser (each feature), script (an exported file equals the bytes `zeff run` writes), snapshot. Done when: the owner can run the example, compare its two figures, pop one out to a second window and save it at one-column size.
