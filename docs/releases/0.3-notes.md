# Zemp Lite 0.3 — The engine of Zeff 0.9.0, the examples of Help run in the page, and Paper: release notes

_Released 27 November 2026, on the owner's word ("Release 0.3")._

## What it is

The preview on a new engine, the released Zeff 0.9.0 (commit
`670e73f8afc6c741a1f65a652c957281531108e9`, tag `v0.9.0`), with two additions of its own, as
the row of section 15 of the Zemp Specification asks: the examples of Help run in the page
(open decision #211, item 11), and **Paper**, a place for `.typ` files, in its first stage
(#172, option A). With them, by decisions placed in this release: a script exported with its
output as a PDF (the row), a project's other text files opened to be read (#228), and the
Variables pane for every kind of variable (#209, option A). Its address is
`https://lite.zeff-lang.dev`.

## What shipped

**The engine of Zeff 0.9.0.** Everything the app runs, checks, prints and draws is the released
engine of 0.9.0. Help counts 266 functions in 11 packages and 148 explained codes. A project
whose `zeff.toml` names another engine is not run as if it named this one: the engine's own
refusal (Z0710) is given, and a line under the bar says which engine the project names, with
**Move to Zeff 0.9.0**, which rewrites that one line.

**The release's methods, through the engine** (#112). The package `glm` (`glm`, `curve`,
`confusion`), `margins`, `summary(exponentiate: true)`, `timer`, `n_chars`, `row_number`,
`row(vars, stat: n_missing)` and `posthoc(method: games_howell)`; a tenth sample project of
binary outcomes; 84 help pages in the fuller form. Nothing was built for them in the app: a
logit, its odds ratios, a marginal effect, the classification table and the ROC curve read on
screen as the released `zeff run` prints them, to the byte.

**More of what is on screen is the engine's own answer.** Each statement's name, type and
dimensions, so that the note of a fit or a test carries its N (`m3 RegFit · N 15,366`); a print
made again at another width without a run; the sections of a script; an error's chain of calls,
which now names the pass of a loop; and a run's figures, laid out by the engine at the size of
their place with nothing run again. Two limits of 0.2 are lifted: the plot of a name bound
again further down is drawn, and so are the plots made before a statement that fails.

**The examples of Help run in the page.** Under every example of a function's page: **Run**,
**Reset** and **Copy to script**. An example's statements can be changed where they stand and
run again; under them is what the engine printed and said, a code of a warning or an error
opening its page, and its plots drawn by the engine in both themes. The examples of a page run
by themselves as it opens, in a session of their own that sees nothing of the reader's project
and changes nothing in it. Every example of every page (270 pages, 1,216 examples) is held by
the build to what its page says, line for line.

**Paper.** A fifth place in the top bar, after Plots, for a paper written in Typst: its source
in the middle in the app's editor, its page at the right, **Project** and **Outline** at the
left.

- _The live page._ The paper is set by Typst a fifth of a second after the last key and drawn
  page by page, to the width of the pane or at a size smaller or larger. Where Typst refuses
  the text its words stand under their line, and the pages of the text as it last set stay,
  marked "not the present text".
- _From the page to the source._ A press on a word, a heading, a table or a figure of the page
  puts the cursor at its place in the source. The Outline lists the paper's headings, each
  going to its place in the source and on the page.
- _Tables and figures from scripts._ A paper sets what scripts wrote with `export`: a table as
  a `.typ` file, a figure as the engine's SVG. **Run** in Paper runs the scripts whose exported
  files the paper uses, and the page is set again. A file the paper lacks is named with the
  script that writes it; a table or figure whose script has changed since it was written is
  said to be stale until a run writes it again.
- _The PDF._ **Export PDF…** saves the paper as Typst sets it. The file holds no time and
  nothing of the machine: the same bytes in Chromium and in WebKit, and, written with a time,
  the file the desktop Typst 0.15.1 writes from the same sources and fonts.
- _A sample paper._ The Scratch project carries one page, "Returns to schooling", with an
  equation, a table of two regressions and a figure, written by a fourth example script.
- _Typst is fetched only when it is needed._ It is a module of Zemp's own, apart from the
  engine: nothing of it travels until a paper is opened or a script exported, and then once,
  7.5 MB with its nine fonts, each file checked against the build's digest.

**Export script with output.** In the Script place's bar and in ⌘K: the script as typed, with
what each statement printed, said and drew, as a PDF set by Typst (A4, a typewriter face, black
on white). Every character of a print is the engine's. A script not yet run is offered **Run,
then export** or **Export the script alone**.

**A project's other text files opened to be read** (#228). A LaTeX table a script exported, a
CSV, any file that is text opens in a tab that says it is read only; where a script is known to
have written it the tab names the script, and **Run** runs that script.

**The Variables pane for each kind of variable** (#209). A text of many values by the lengths
of its values, with its first five values and those that repeat; a text of few values with the
line naming `category()`; a variable whose every value differs said to look like an identifier;
an ordered category in the order of its levels; a number with the unit and the measure its data
carries. Every figure is a cell of what the engine prints.

**A wrong file never kept for a year** (risk R13). The host answers the address of a built
file that it does not hold as no file, not to be kept, for every built file of the app, and the
page says so in a line with **Load again** when one of its scripts did not arrive.

**Using Zemp Lite.** A fourteenth page, **Papers and PDFs**; new sections in **Finding help**
(running an example) and in **Projects, scripts and files** (a project that names another Zeff;
files opened to be read); all fourteen pictures made afresh from the app.

## Breaking changes

None of Zemp's own for a project's files. From the engine, as the notes of Zeff 0.9.0 list
them: a warning repeated in a loop is printed once with its count; six printed layouts changed;
an imported column of whole numbers is widened to Float at a decimal; the note under a weighted
test; `compare` refuses fits that do not belong together; a script's own function is no longer
called by a name the release adds. On screen:

- A project made in an earlier Zemp Lite names Zeff 0.8.0 and is not run until it is moved:
  one press of **Move to Zeff 0.9.0**. The Scratch project of an earlier visit is moved without
  the asking.
- The top bar has a fifth place, **Paper**, and the Script place's bar a new command, **Export
  script with output**.
- A project's folder gains `paper/` when a paper is made. Which script wrote which file is
  kept in the browser beside the project's view state (`.zemp/written.json`); like that state
  it is not part of an exported project, so a project opened from a zip marks nothing stale
  until its scripts have run there.

## Reference versions

Every output is held to what the released Zeff 0.9.0 command line prints, writes and says for
the same script, byte for byte: the ten sample projects, the Scratch project's four scripts,
the code of the pages of **Using Zemp Lite**, and every example of Help. A paper and a script's
PDF are set by Typst 0.15.1, built from the released program's own lock file, with hyphenation
for 33 languages (those whose patterns are under licences this project links) and nine fonts
carried as files: Libertinus Serif (four, Typst's own copies), DejaVu Sans Mono (four, Typst's
own copies) and Libertinus Math 7.051. The PDFs are held to kept digests, and one of them to the
file the desktop Typst 0.15.1 writes.

## What is left out, and why

Of Paper, its later stages: the settings file, `refs.bib`, citations and cross-references
checked as one types, and the Article template (Zemp 0.4); a script's named values written to a
`.typ` file (#219, proposed for Zeff 0.10.0); `.zmd` papers (after 1.0). Mathematics is set in
Libertinus Math, not New Computer Modern Math, whose licence this project does not ship; a new
paper names the face in its first line. Of the Variables pane: an opaque column, which Zeff
0.9.0 does not have, and an ordered category's cumulative share and median level, which the
engine does not print. **Run section** and **Run from a fresh session** as the engine's own
(#178, #180). The pages of Help reordered (#223), a release of its own. The index of methods
(#211, stage 2). The fonts of a figure (#222, Zeff 0.10.0). **Open folder…** as a working card:
with the desktop app.

## Known issues

- Which files a script would write is read from its text (the paths in its calls of `export`);
  a path built from other values is not seen, so such a file is not named with its script and
  is not marked stale.
- The examples of the explained codes are shown as the page's illustration and are not run:
  as they stand, most print something other than their page says. It is put to the engine's
  registers.
- Hyphenation is from newer patterns than the desktop Typst carries (33 languages, those under
  licences this project links), so a justified paper in German, Finnish, Portuguese or Albanian
  may break its lines differently from the released desktop Typst.
- The page of a paper is a picture: by the keyboard the Outline goes to each heading, but a
  word of the page cannot be stood on. The pages' view takes the keyboard and scrolls by the
  arrow keys.
- A window narrower than 1,200 pixels still says that the app is laid out for 1,200 pixels
  (#33); Paper has no layout of its own for a phone.
- On GitHub's machines, in Chromium, the first ⌘↵ of a session has sometimes waited about three
  seconds before its run began; of it the app's own work is tens of milliseconds, and it has
  not been seen on a reader's machine.
- The reader test is not run (moved by the owner to Zeff 0.11.0, #230), and the checks by hand
  are not made (the keyboard alone on a real keyboard, VoiceOver, Safari itself).

## Measures

At `https://lite.zeff-lang.dev`, on the build of the pre-release commit (`78a2bb5`), from
GitHub's machines in the two engines (Chromium first, then WebKit), and from the owner's Mac in
Chromium on the build before it. The trial address, where each build is tried first, is given
where it differs.

- The engine as it travels: **3.1 MB** (3,073,706 bytes in Chromium, 3,077,216 as WebKit counts
  them), of the 5 MB of risk R4; 5 per cent more than at 0.2.5, for one more package.
- Typst as it travels, the module and its nine fonts, once, when a paper is first opened:
  **7.5 MB** (7,535,496 bytes in both engines and from the Mac), of the 8.5 MB allowed. Nothing
  of it is fetched at the start of the app, which a test holds.
- The first start, timed to the engine running: 1.05 s and 2.00 s, the goal being 2 s (at the
  trial address 0.82 s and 2.20 s; from the Mac 1.1 s). WebKit stands at the goal with no room,
  as it has since 0.2.5.
- The first paper, from **Paper** being pressed to the sample paper's first page drawn, Typst
  fetched on the way: 1.99 s and 2.01 s, of which Typst's setting of the page is 0.24 s and
  0.13 s (from the Mac 1.3 s, the setting 70 ms).
- A keystroke to its page: 0.30 s and 0.33 s from the key to the page drawn anew, of which
  0.2 s is the pause for the typing to rest and Typst's setting 5 to 7 ms (from the Mac
  0.24 s; at the trial address once 0.50 s in WebKit, 0.26 s at the next key).
- ⌘↵ on one statement, from the key to "done": 65 ms in WebKit and 52 to 53 ms at the trial
  address; in Chromium at the address 2.7 s, all but 29 ms of it before the run began, which
  is the wait of the known issues (from the Mac 21 ms).
- These times are mostly the network's. At the walk, an hour later on the same Mac, the first
  start took 4.6 to 6.5 s and the first paper 6.6 to 7.3 s, the same bytes travelling.
- A plot drawn afresh: 27 to 47 ms (0.24 to 0.29 s at the trial address). A run's figures
  first drawn: 0.32 to 0.35 s after "done".

## The validation suite

The routine on every change: format, lint, types, the edition check, the Rust checks of the
worker and of the Paper module with their 86 native tests, the messages of both under Node, the
two measures (the engine 3,085.3 kB with its script, of 5,000; the Paper module 7,535.5 kB, of
8,500), the ten sample projects identical to what `zeff run` prints, the tests of what the
build takes from the engine and of the host's function, 550 unit tests and 825 browser tests in
Chromium and WebKit (3 skipped by design); at each deployment, 18 checks at the trial address
and then at the address in the two engines, now with the measures of Paper among them.

At the pre-release routine (step 23, on commit `78a2bb5`):

- _Features frozen._ The release's own tree differs from that commit in the version, the
  pictures that show it and the documents alone.
- _The pictures made afresh._ All fourteen: seven came out identical to those made an hour
  before, and seven differ only in a time of day or a run's duration.
- _The routine._ Green on GitHub in both browsers, every part of it. On the owner's Mac, green
  in every part but five browser tests in WebKit, which timed out at a mouse click when the
  machine's screen locked while they ran; the five pass when run again by themselves.
- _The deployment._ That commit was sent to the trial address and then to the address, and all
  18 checks passed at each. (The deployment of the commit before it never began: GitHub's
  machine could not install the test browsers, a package server of its own refusing it. Nothing
  was sent, and the next deployment went through.)
- _The ten sample projects read by eye in the app,_ each opened from a zip and run: nine print
  what `zeff run` prints to the character; the tenth, `plots`, prints the same words with one
  wide table unwrapped, the window being wider than 80 columns, and its figures are in
  Plots. Tables stand in their columns, notes and warnings under their statements, and the
  letters of the German spreadsheet are right.
- _The walk at the address, in the two engines._ As a first visitor: the loading screen to
  "Ready, 100 %" with "3.1 MB, once", **Start** pressed by Return, the project screen, the
  Scratch project; a logit of union membership with its odds ratios, a marginal effect and the
  classification table (8 statements in about 0.1 s), and its ROC curve in Plots with the area
  under it; the page of `glm` in Help, its seven examples each "run by the engine"; **Paper**
  pressed for the first time, nothing of Typst having been asked for before, and the sample
  paper on the page; **Export PDF…** saving `paper.pdf`,
  151,792 bytes, the same file in both engines and the one the tests keep. As a returning
  visitor: no loading screen; a project that names Zeff 0.8.0, as every project of 0.2.5 does,
  opened from a zip, refused a run with the line that says why, moved by one press and run; in
  Chromium found again among the projects opened last, opened and run with no line. WebKit's
  test browser keeps no project between pages, so the last part was seen in Chromium alone.

At the release, on its own tree (the version 0.3.0, nine pictures made again for the version
they show and a time of day, and the documents): the whole routine green on the owner's Mac in
both browsers, 550 unit tests and 825 browser tests (3 skipped by design), the ten samples
identical, the engine 3,088.6 kB with its script and the Paper module 7,535.3 kB. GitHub's
check of the release's commit and its deployment are read after the tag is pushed.

Not run or not checked at this release: the reader test (moved by the owner to Zeff 0.11.0,
#230) and the checks by hand (the keyboard alone on a real keyboard, VoiceOver, Safari
itself).

## To try it

Open `https://lite.zeff-lang.dev` in Chrome, Edge or Safari, press **Start** and choose
**Scratch project**. Press **Paper**: Typst comes once (7.5 MB) and the sample paper is on the
page; type in its source and watch the page follow; press a word of the page; press **Export
PDF…**. In **Script**, press **Run** and then **Export script with output**. In **Help**, open
the page of `glm` and change an example where it stands. The address is not announced until the
trademarks are filed (#37).
