# Zemp Lite 0.2 — The alpha

Released 22 November 2026, version 0.2.0, tag `v0.2.0`, after the owner had tried the alpha at
its address and said "Release 0.2" (late on 21 November). Drafted at step 19a and completed at the
release.
The reader test and the acceptance tests left for the hand move to 0.2.1, by the owner's decision
of the same day.

## What it is

Zemp Lite web, the first public preview of the editor for Zeff in a browser, on the released
Zeff 0.8.0 engine (commit `6bfa6c55a5584e4e038fc828fef900a30f0856c3`, tag `v0.8.0`), built to
WebAssembly and run in the browser. Its address is `https://lite.zeff-lang.dev`.

## What shipped

**The margin editor** (open decision #174, the design of 21 November 2026). The script fills
the window as plain text; beside each statement a note in the engine's words (`wages Frame ·
15,571 × 13`); a script opens folded, a note unfolds its output, printed by the engine at the
width of its place; **Notes · Fold all · Unfold all**, kept with the project; ⌘↵ runs the
statement at the cursor with what it needs, **Run to here** and **Run from here**; what is
stale marked by the safe rule; the run's facts, what it said and an error's trail; a loop's
passes; Panes kept beside it (R2).

**The engine's language server** in a second worker: diagnostics as one types, what a name is
on resting over it, completion, the usage of a call, formatting.

**Help** (#74): the Help panel, F1 and `:help`, the engine's own pages.

**The places** Script · Data · Plots. **Data** (#75, option A): the frames of the run, a grid
drawn as it is scrolled, every cell the engine's, variables shown and hidden, the inspector with
the engine's summary, sorting (the kernel of `data.sort`), **Keep rows where** (a run of
`wages.where(…)` by the engine), search, the live count of rows, each header's distribution in
the engine's histogram bins, copying a range, **Copy as Zeff** (#114). Each column of the grid is as wide as its header, so a variable's name,
type and count of NA show whole (a mend of the release day, from the owner's trial). **Plots**:
the list of plots at the left, with 0.1's viewer; a plot bound with `let` is drawn under its
statement and listed by its name.

**The console line**: `:help`, `:vars`, `:save` as `zeff repl` has them, `:clear`; ⌘↵ copies a
line into the script.

**Report a problem**: the engine's own bug report, built in the browser as `zeff report-bug`
builds it, read whole and saved by the user; nothing is sent.

**The first visit**: the Start screen (the engine fetched, checked against its digest, started);
the Scratch project with the returns to schooling on `wages` and the engine's `instruments`
sample on `staff`, and the showcase of plots, 21 plots from one line to a finished figure for a
journal (the owner's answer of 21 November 2026); **alpha** and what it means; **What is
counted** (#116, layer 1), counted by the host's cookie-free Web Analytics.

**The host** (#27): Cloudflare Pages, at `https://lite.zeff-lang.dev` (its domain locked,
with DNSSEC); the headers file; a deployment from every green commit of the main branch; and
the checks after each deployment, at both of the project's addresses: every answer's headers,
the engine started in Chromium and WebKit, and the first start, a statement run alone and a
plot drawn afresh, timed.

## Breaking changes

None for a user's project: the views file is read as before (version 2, unknown parts kept) and
gains the data viewer's views. A Scratch project made before is kept as it is, and is given the
examples it does not have, once each; a new browser's Scratch project holds all three.

## Reference versions

Every output is held to what the released Zeff 0.8.0 command line prints, writes and says for
the same script (`zeff run`, `zeff check`, `zeff help`, `zeff explain`, `zeff repl`,
`zeff report-bug`), byte for byte; no other software is a reference for Zemp. The engine's own
validation against R, Stata and Python is Zeff's (its release notes of 0.8.0).

## What is left out, and why

The engine of 0.8.0 does not yet give an interface these, so the alpha works round them, as the
shared notes record (items placed at Zeff 0.9.0 and 0.11.0):

- a result's size (C5): the note gives the type and the first printed line;
- a print at a width without a run (C6): the output is run again at the new width;
- results kept between runs (C14): a run of part of the script runs from the top;
- a plot handed over (C16): the figure is exported and read back, as in 0.1;
- the error's chain as fields (C22): the trail is read from the printed text;
- what each pass printed and made (C23): a loop's passes give their number and time;
- each statement's time (C26): timed by the interface.

Not in this alpha: the outline of sections (#178; it comes with 0.2.1), a comparison with an earlier
run, the passes searched and opened by replay (R16 to R18), Paper (#141), sorting by several
variables, the data shrunk into a report (`--include-data`).

Coming in 0.2.1, on the same engine (the owner's decision of 21 November 2026): one layout of three
panes on every place, each opened and closed by its own link (Project, Outline and Notes beside the
script; the frames and a read-only Variables pane beside the data; the plots and the plot's facts;
the help page's outline and its related functions), with **Panes** and the Objects panel removed and
**Run** unfolding every output. The reader test and the checks by hand (the keyboard alone,
VoiceOver, the print at every size) are run on 0.2.1.

## Known issues

- Staleness follows the safe rule: an edit marks every result below it, where the engine would
  reuse some (the engine's flags come with 0.9.0).
- In Safari, a run started from the keyboard just after typing brings the cursor's line into
  view; Chrome and Edge leave the reader where they are.
- A reload within half a second of a change can lose that change of the view (not of the script).
- The first start can pass section 14's 2 seconds on a slower connection: at the address it took
  1.4 s in Chromium and 2.0 s in WebKit from GitHub's machines, and 2.3 to 4.6 s from the
  owner's machine through Cloudflare's Mumbai edge, almost all of it the 4.07 MB of the engine
  (Cloudflare compresses it less tightly than the build's own 2.92 MB). A later visit fetches
  only the page.
- Visits from Safari may go uncounted: at the release, WebKit refused the counter's report to
  Cloudflare's Web Analytics under its access checks, while Chromium sent it. Nothing else is
  affected, and nothing about the visitor is sent either way.
- A plot bound with `let` whose name is bound again later in the script is not drawn (the
  name then holds another value at the end of the script); the engine's hand-over of plots
  (C16) removes the limit.

## The design's acceptance tests (its section 21), as they stand at the release

*Holds* names the tests that hold it; *not built* says what it waits for; *by hand* is checked
on the hosted alpha at 0.2.1, with the reader test (the owner's decision of 21 November 2026).

**Principles.** Running inserts and moves no text: holds (`figure.spec`, `margin.spec`). The
opened result is what `zeff run --width n` prints, and Copy as text what `zeff run` prints:
holds (`margin.spec`, the native tests at each width). No number in a note formatted by the
interface: holds (`notes.node.test`). No control writes to the script but the console line's
copy: holds, with one more writer named here: **Format the script** in ⌘K, which writes the
engine's formatted text when asked. View changes alter no export or result: holds for the data
viewer's hiding (`data.spec`); the rest by hand.

**Script.** Opened with no output unfolded; one note per statement; no estimate in a note; an
output holds only what the engine said and printed; Unfold all, Fold all, Notes; several open at
once: hold (`margin.spec`). Each step of a chain its own note: not built (C5). Staleness exactly
as the engine would reuse (line 5 of the example, spacing, comments, shadowing, random draws):
not built, the safe rule (the engine's flags, 0.9.0). A console statement marks nothing: holds
by construction (it never edits the script); by hand. ⌘↵ on a statement whose input is stale
runs that input first; a result below a run of one statement is stale: hold (`margin.spec`). A
refused script runs nothing and shows the engine's message under its line: holds (`check.spec`,
`margin.spec`). A comparison with an earlier run: not built. Every warning in the margin and the
list with the same code, sentence and line: holds (`margin.spec`). Section comments: not built
(#178).

**Finding a fault.** Every line an error inside a function names is a link: holds (`margin.spec`;
each argument's size waits for C22). A loop's passes in order, a failed loop ending on the pass
the engine reported: holds (`margin.spec`); 200,000 passes in under 100 ms: by hand. *Find the
first pass that…*, `iterate`'s states, opening a call, the console line inside a call: not built
(R16 to R18, C23). The times in the run record are the interface's (C26). Run to here on resting
over a line number, and in ⌘K: holds (`margin.spec`).

**The print at every size.** A fit's table read in full at 1,080 and 1,320 pixels, at 200% zoom,
at the largest code size, in the dark theme, with a term 40 characters long: by hand.

**Places.** What Data and Plots show names its line: holds (`data.spec`, `viewer.spec`). A
missing value never blank: holds (`data.spec`); a row left out naming its condition: not built.
`report()` notes on columns that differ, and `coef_plot()`: the engine's, not in 0.8.0. A figure
the engine's, never stretched: holds (`figure.spec`). Unticking a variable, hiding kept for each
frame, **‹ Hide**: hold (`data.spec`, `viewer.spec`). The list of plots with the console line's
apart: holds (`viewer.spec`).

**Paper.** Not in this alpha (#141).

**Accessibility and scope.** Text at 4.5 to 1 or more: holds for every pair of the colours
(`tokens.test`); none under 12.5 px: holds (one console mark at 12 px found at this draft and set
to 12.5). Every control by keyboard with visible focus, every keyed action in ⌘K: by hand. A
screen reader learns each statement's state, the warnings and what is stale: by hand, with
VoiceOver. Every command in ⌘K says whether it is built: holds, as only built commands are
listed.

## Measures

- The engine's worker: 15.1 MB, **2.92 MB** with brotli as it travels (the limit of risk R4:
  5 MB); a cold start under Node of 55 ms, a project opened and a line run included (measured again
  at the release: 2,919.9 kB and 55.3 ms).
- The first start, from the first request to the engine ready (section 14's goal: 2 seconds):
  on a local build 0.2 to 0.4 s; at `https://lite.zeff-lang.dev` from GitHub's machines 1.4 s
  in Chromium and 2.0 s in WebKit; from the owner's machine 2.3 to 4.6 s.
- A plot drawn afresh for a new size of its place (a run of the script with its `export`): 160
  to 175 ms at the address from GitHub's machines, about 75 ms on this machine.
- ⌘↵ on the last statement of the returns to schooling, which runs it with what it needs from
  the top, three regressions included: 2.2 s in Chromium on GitHub's machines, 0.7 s on this
  machine. (WebKit's figure, under 40 ms, is not taken as a measure until it is checked by
  hand, at 0.2.1.)

## The validation suite

The routine on every change, run again in full at the release on this Mac and on GitHub: format,
lint, types, the edition check, the Rust checks, 28 native tests of the worker, the worker's
message tests, the measure, the nine sample projects of Zeff 0.8.0 identical to what `zeff run`
prints, 166 unit tests and 288 browser tests in Chromium and WebKit (2 skipped by design); after
each deployment, the checks at both addresses. At the close the three examples were run at
`https://lite.zeff-lang.dev` in Chromium and WebKit as a first visitor, every output unfolded
and read by eye against what `zeff run` prints: the same, with no error. The reader test runs on
0.2.1.

## To try it

Open `https://lite.zeff-lang.dev` in Chrome, Edge or Safari, press **Open Zemp Lite**, choose
**Scratch project** and press **Run**. The address is not announced until the trademarks are
filed (question 2 of the release, #37).

## Corrections, found while 0.2.1 was built (22 November 2026)

The text above stands as it was released. Three things in it were found wrong since:

- **The notes were not seen.** "What shipped" says a note stands beside each statement. In 0.2
  the notes were drawn 300 pixels too far right, outside the page; the tests asked that a note
  was there, never where. Mended in 0.2.1, with a test of where each note stands.
- **The console line's plots are not listed apart.** The acceptance tests say this holds, by
  `viewer.spec`. No test held it, and the list of plots holds the plots of the script's run
  alone. It is not built.
- **⌘↵ on the last statement does not as a rule take 2.2 seconds.** The run itself takes a few
  milliseconds in both engines, and the key to "done" tens: WebKit's figure, which these notes
  did not trust, was right. In Chromium on GitHub's machine the key to "done" was still about
  2.5 seconds at one of the three deployments checked last on 22 November (38 and 47 ms at the
  other two, and 14 to 20 ms from a Mac in every trial), with the run itself 31 ms. What it
  waits for there is not yet found; it is a known issue of 0.2.1.
